# rgordeev.github.io

Личный сайт Романа Гордеева на GitHub Pages: главная страница, записи
и отдельные HTML-публикации. Первая запись — программа жима лёжа
от тяжёлых 90 кг к уверенным 90 и попытке 100 кг.

Сайт состоит из готовых HTML и CSS. Для публикации используется стандартная
обработка GitHub Pages через Jekyll: HTML без front matter копируется как
статический файл. Тема, плагины и отдельная сборка фронтенда не нужны.

## Структура проекта

| Путь | Назначение |
| --- | --- |
| `index.html` | Главная журнала: автор, публикация, выбор недели и справочные ссылки |
| `404.html` | Страница для отсутствующего адреса |
| `assets/favicon.svg` | Значок сайта |
| `assets/journal.js` | Открытие выбора недели по ссылке из шапки; необязательное улучшение навигации |
| `stylesheets/stylesheet.css` | Оформление главной страницы и страницы 404 |
| `_config.yml` | Название, описание и исключения Jekyll; без темы и плагинов |
| `publish/bench-press-90-to-100.html` | Автономная HTML-публикация с собственными стилями, схемами и скриптом |
| `publish/raw/`, `publish/work/` | Локальные исходники и результаты проверки; исключены из Git и публикации |
| `scripts/setup-git.sh` | Повторяемая настройка Git для этого репозитория |

В репозитории нет `Gemfile`, закреплённых версий зависимостей, тестов или
собственных workflows GitHub Actions. Настройка Git не проверяет сборку сайта.

## Локальный просмотр

Из корня репозитория запустите:

```sh
python3 -m http.server 4173 --bind 127.0.0.1
```

Откройте [главную страницу](http://127.0.0.1:4173/)
или [первую запись](http://127.0.0.1:4173/publish/bench-press-90-to-100.html).
Для остановки сервера нажмите `Ctrl+C`.

Локальный сервер позволяет проверить HTML, оформление и ссылки без Jekyll.
Он не воспроизводит исключения из `_config.yml` и не подтверждает публикацию
на GitHub Pages.

## Добавление записи

1. Поместите готовую автономную HTML-страницу в `publish/`, например
   `publish/my-post.html`. Стили, скрипты и схемы можно включить в сам HTML,
   как в первой записи. Добавьте ссылку `../` для возврата на главную.
2. Разрешите файл в `.gitignore` отдельной строкой `!/publish/my-post.html`.
   Остальные материалы каталога остаются локальными.
3. Добавьте карточку со ссылкой `publish/my-post.html` в раздел записей
   `index.html` и обновите счётчик записей.
4. Проверьте страницу и переходы локально, затем добавьте готовый HTML
   и изменения главной страницы в Git.

Публикации сохраняют свои адреса вида `/publish/my-post.html`.
Локальные исходники из `publish/raw/` и `publish/work/` для них не требуются.

## Навигация главной

Новый читатель может сразу открыть программу или обзор всех недель. Для
повторного визита блок «Недели и правила» содержит выбор одной из 12 недель
и ссылки на правила нагрузки, разминку и технику жимов. Выбор недели использует
стандартный HTML `details`; все переходы работают без JavaScript.
Небольшой скрипт дополнительно раскрывает выбор недели и переводит фокус на
него при переходе из шапки. Прямой адрес главной с `#week-picker` также
раскрывает выбор. Номер недели не сохраняется и не обозначает прогресс.

Якоря `#main` и `#notes` на главной сохраняются для обратных ссылок из статей.

## Настройка Git

После клонирования выполните:

```sh
sh scripts/setup-git.sh
```

Скрипт меняет только `.git/config` текущего репозитория. Глобальная конфигурация,
автор коммитов, адрес `origin` и основная ветка `master` сохраняются.
Настройки из `.git/config` не передаются при клонировании, поэтому скрипт нужно
запустить в каждой новой локальной копии.

| Настройка | Результат |
| --- | --- |
| `core.autocrlf=false`, `core.eol=lf`, `core.safecrlf=true` | Окончания строк задаёт `.gitattributes`; Git отклоняет небезопасное преобразование |
| `core.quotePath=false` | Кириллические имена файлов отображаются читаемо |
| `fetch.prune=true` | Удаляются устаревшие ссылки на удалённые ветки при fetch; локальные ветки сохраняются |
| `pull.ff=only` | `git pull` останавливается при расхождении истории; способ объединения выбирается явно |
| `push.default=simple`, `push.autoSetupRemote=true` | Push текущей ветки с проверкой имени upstream; первый push новой ветки назначает upstream |
| `diff.algorithm=histogram`, `diff.renames=true` | Более читаемый diff с распознаванием переименований |
| `merge.conflictStyle=zdiff3` | В конфликте виден исходный текст общего предка |
| `rerere.enabled=true`, `rerere.autoupdate=false` | Git запоминает разрешения конфликтов; повторно применённое решение нужно проверить и добавить в индекс вручную |
| `commit.verbose=true` | В редакторе сообщения коммита виден подготовленный diff |
| `transfer.fsckObjects=true`, `fetch.fsckObjects=true` | Git проверяет получаемые объекты |
| `http.sslVerify=true` | Для HTTPS включена проверка сертификатов |

На macOS при наличии `git-credential-osxkeychain` скрипт сбрасывает унаследованный
список HTTPS credential helpers для этого репозитория и включает системную
Связку ключей. SSH-доступ к `origin` использует существующие SSH-ключи.
На других ОС список credential helpers сохраняется.

### Общие правила файлов

- `.gitignore` исключает содержимое `publish/`, кроме явно разрешённых готовых
  HTML-публикаций, а также результаты сборки и кеши Jekyll, локальные зависимости,
  окружения Python, `.env` и служебные файлы ОС.
  Шаблоны `.env.example`, `.env.sample`, `.env.template` можно отслеживать.
- `.gitattributes` задаёт LF для текстовых файлов и отключает текстовые
  преобразования для изображений, PDF и шрифтов.
- `.editorconfig` задаёт UTF-8, LF, завершающий перевод строки и отступы.
  Пробелы в конце строк Markdown сохраняются, поскольку могут задавать переносы.

Перед коммитом просматривайте подготовленный diff.

## Обычная работа

```sh
git status --short --branch
git pull
git switch -c update/personal-site
# Отредактируйте нужные файлы, затем добавьте их явно.
git add index.html stylesheets/stylesheet.css
git diff --cached --check
git diff --cached
git commit -m "feat: update personal site"
git push
```

При отказе `git pull` из-за расхождения истории сначала выполните `git fetch`
и изучите `git log --oneline --graph --decorate --all`. Затем явно выберите
merge или rebase с учётом того, опубликованы ли ваши коммиты.

Текущая основная ветка — `master`, upstream — `origin/master`, remote —
`git@github.com:rgordeev/rgordeev.github.io.git`. Параметры публикации GitHub Pages
проверяются в настройках репозитория на GitHub; локальная конфигурация Jekyll
сама по себе не подтверждает источник и успешность публикации.
